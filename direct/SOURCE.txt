Direct browser port of id Software LinuxDOOM 1.10
=================================================

Engine/game source baseline:
https://github.com/id-Software/DOOM
pinned commit: a77dfb96cb91780ca334d0d4cfd86957558007e0

Browser platform and MCP source:
https://github.com/pavy23/web-doom/tree/direct-linuxdoom/direct-port
https://github.com/pavy23/web-doom/tree/direct-linuxdoom/mcp

Build: Emscripten 6.0.5 + SDL2 + SDL2_mixer.
Gameplay/rendering/game-state remain id Software LinuxDOOM.

Audio:
- Direct DMX type-3 SFX playback through SDL2_mixer.
- Vanilla/DMX-compatible OPL behavior from pinned Chocolate Doom
  commit 410d96855b5df5410ff591a90efeafa889119224.
- Nuked OPL3 v1.8 in OPL2-compatible nine-voice mode by default.

MCP / AI authoring + autonomous playtest (v0.8):
- Persistent authoring still rewrites only THINGS, LINEDEFS, SIDEDEFS
  and SECTORS while topology/BSP-derived map lumps stay unchanged.
- v0.7 pause, exact P_Ticker stepping, telemetry and PNG frame capture
  remain the observation layer.
- doom_agent_input.c adds a bounded console-player ticcmd override for
  forward/back, strafe, turn, attack and use. It is playtest-only.
- patch_agent_input.py inserts the override after LinuxDOOM G_Ticker()
  selects the actual local net/demo command and before gameplay consumes it.
- Autonomous input lifetime is decremented only after an actual P_Ticker
  world update, so paused browser frames cannot consume planned input.
- doom_run_input combines one bounded input with an exact world-tic budget,
  leaving the world paused for deterministic frame/telemetry evaluation.
- doom_run_input_sequence executes up to 16 short actions with a bounded
  total simulation budget and stops early on player death.
- AI actions never synthesize BT_SPECIAL/save/pause/weapon-change commands
  and never persist into exported PWADs.
- Authoring remains on 127.0.0.1:3777/control; playtest/vision/agent traffic
  uses 127.0.0.1:3778/playtest only when loaded through the local MCP proxy.

Loop:
AI inspect -> edit -> short input -> exact tics -> frame + telemetry
-> evaluate -> next action or revise -> PWAD export/reload.
