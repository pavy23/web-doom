Direct browser port of id Software LinuxDOOM 1.10
=================================================

Engine/game source baseline:
https://github.com/id-Software/DOOM
pinned commit: a77dfb96cb91780ca334d0d4cfd86957558007e0

Browser platform and MCP authoring source:
https://github.com/pavy23/web-doom/tree/direct-linuxdoom/direct-port
https://github.com/pavy23/web-doom/tree/direct-linuxdoom/mcp

Build system: Emscripten 6.0.5 + SDL2 + SDL2_mixer.
Gameplay/rendering/game-state remain id Software LinuxDOOM; browser
platform boundaries and explicit authoring adapters live in this repo.

Sound effects:
- DOOM DMX type-3 DS* lumps are parsed directly into SDL2_mixer.
- Original PCM, pitch variation, volume and stereo separation are used.

Music:
- Vanilla/DMX-compatible OPL behavior is imported from pinned Chocolate Doom
  commit 410d96855b5df5410ff591a90efeafa889119224.
- Nuked OPL3 v1.8 renders in OPL2-compatible nine-voice mode by default.
- The earlier WebAudio oscillator approximation is retired.

MCP / AI level authoring (v0.6):
- doom_control.c: player/enemy/sector state, actor edits, sector-light edits,
  ChangeSet core and PWAD writer.
- doom_linedefs.c: existing LINEDEFS inspection, allow-listed Vanilla door
  actions, special/tag journal and P_UseSpecialLine() playtest.
- doom_visuals.c: nearby sector/sidedef material inspection, valid IWAD wall
  texture/flat enumeration, live wall texture + floor/ceiling flat edits,
  and SIDEDEFS/SECTORS persistence.
- Visual edits are asset-validated: wall names use R_CheckTextureNumForName()
  and flats must resolve inside the loaded F_START..F_END range.
- Persistent export rewrites THINGS, LINEDEFS, SIDEDEFS and SECTORS while
  VERTEXES/SEGS/SSECTORS/NODES/REJECT/BLOCKMAP remain unchanged.
- No v0.6 authoring operation moves vertices or changes topology.
- doom_export_pwad writes a real current-map PWAD; mcp/server.js stores it
  under mcp/exports/ (or DOOM_MCP_EXPORT_DIR).
- doom_load_pwad validates in Node and C, grows LinuxDOOM's lumpcache,
  appends through W_AddFile(), and rebuilds via G_InitNew().
- Imported PWAD becomes the fresh baseline; actor/sector/linedef/visual
  ChangeSets reset together after successful reload.
- Loading/reloading protects all unexported authoring edits by default.
- Heal/ammo/player teleport and linedef activation are playtest-only.

Authoring loop:
AI inspect -> actor/logic/lighting/material edit -> playtest -> ChangeSet
-> PWAD export -> PWAD reload -> LinuxDOOM map rebuild -> next iteration.
