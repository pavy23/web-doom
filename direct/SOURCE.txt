Build: Emscripten 6.0.5 + SDL2 + SDL2_mixer.
Gameplay/rendering/game-state remain id Software LinuxDOOM.

Audio:
- Direct DMX type-3 SFX playback through SDL2_mixer.
- Vanilla/DMX-compatible OPL behavior from pinned Chocolate Doom
  commit 410d96855b5df5410ff591a90efeafa889119224.
- Nuked OPL3 v1.8 in OPL2-compatible nine-voice mode by default.

MCP / AI authoring + autonomous design evaluation (v0.9):
- Persistent authoring still rewrites only THINGS, LINEDEFS, SIDEDEFS
  and SECTORS while topology/BSP-derived map lumps stay unchanged.
- v0.7 pause, exact P_Ticker stepping, telemetry and PNG frame capture
  remain the observation layer; v0.8 bounded ticcmd input remains agency.
- evaluator.js adds deterministic hard constraints and weighted scoring
  over deaths, final health, damage, traversal, stuck actions, kills and pacing.
- Optional AI-vision rubric scores can be attached to a stored trial so
  atmosphere/readability/navigation judgments share one evaluation report
  with engine telemetry instead of replacing the measurable metrics.
- doom_run_design_trial resets the metric window, executes up to 16 bounded
  input actions (700 world tics total), stores per-action before/after data,
  calculates a score, and returns the final PNG for visual inspection.
- doom_evaluate_playtest re-scores live telemetry or a stored trial, including
  optional visual assessments and explicit reasons for failed criteria.
- doom_get_trial_history and doom_compare_trials preserve up to 20 recent
  in-process trials so authored WAD iterations can be ranked by the same goal.
- Evaluation is advisory and playtest-only; it never mutates or serializes
  level content. The final playable artifact remains an ordinary PWAD.

Loop:
AI goal -> author -> deterministic trial -> telemetry score + final frame
-> vision rubric -> evaluate -> revise or accept -> PWAD export/reload.
